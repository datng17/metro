Metro backend (metro-be) on AWS

Kiến trúc AWS đề xuất cho hệ thống microservices Spring Boot 3.4 / Spring Cloud của metro-be: 9 service chạy trên ECS Fargate trong private subnet, đi vào qua Route 53, AWS WAF và Application Load Balancer, dữ liệu trên RDS PostgreSQL, ElastiCache Redis, DocumentDB và Amazon MQ (RabbitMQ). Keycloak và PocketBase chạy trên EC2, chatbot dùng Amazon Bedrock, push mobile dùng Amazon SNS. Hiện tại hệ thống chạy bằng Docker Compose / Portainer trên ZimaOS với Neon, MongoDB Atlas và Docker Hub; bản vẽ này là phương án chuyển lên AWS, không phải hạ tầng đang chạy.

Bấm một chip để làm nổi luồng, Next để đi từng mũi tên, bấm vào một thành phần để xem vai trò của nó.

Các luồng chính
  1. API requests. Client gọi HTTPS tới domain trên Route 53, qua Internet Gateway, AWS WAF và ALB. Domain API tới gateway-service, gateway tra eureka-service và chuyển request theo path tới auth, user, station, ticket, order hoặc notification; domain auth tới Keycloak trên EC2.
  2. Data access. gateway và auth-service dùng ElastiCache Redis; user, station, ticket, order, notification, cronjob và Keycloak dùng RDS PostgreSQL, mỗi bên một schema; station-service đọc dữ liệu bus từ DocumentDB; user-service đọc blog từ PocketBase trên EC2.
  3. Async events. station-service phát station.add / station.delete để ticket-service cập nhật vé (có DLQ); order-service phát order.completed để notification-service gửi email và push.
  4. Third-party APIs. Task trong private subnet đi ra Internet qua NAT Gateway, chỉ còn Stripe, PayPal, VNPay (có callback về qua ALB) và Google / Facebook OAuth.
  5. CI/CD. GitHub Actions build từng service bằng Maven và Docker, push image lên Amazon ECR, sau đó ECS Fargate kéo image mới khi service được cập nhật.
  6. AWS APIs. user-service gọi Amazon Bedrock cho chatbot; notification-service gửi push qua Amazon SNS và email qua Amazon SES. Cả ba đi qua VPC interface endpoint và xác thực bằng IAM role của task.
Ánh xạ từ hạ tầng hiện tại sang AWS
  • Docker Compose / Portainer trên ZimaOS sang ECS on Fargate, mỗi service một ECS service và task definition.
  • Keycloak (kc.lch.id.vn) sang Keycloak trên Amazon EC2, sau ALB, database trên RDS.
  • PocketBase (pkb.lch.id.vn) sang PocketBase trên Amazon EC2, dữ liệu trên EBS.
  • OpenAI gpt-3.5-turbo sang Amazon Bedrock.
  • Firebase Cloud Messaging (Admin SDK) sang Amazon SNS mobile push.
  • Neon PostgreSQL và container postgres 17.4 sang Amazon RDS for PostgreSQL Multi-AZ, giữ mô hình schema theo service.
  • MongoDB Atlas sang Amazon DocumentDB.
  • Container redis 7.2.3 sang Amazon ElastiCache for Redis.
  • RabbitMQ (localhost:5672) sang Amazon MQ for RabbitMQ.
  • Docker Hub lcaohoanq/metro-* sang Amazon ECR.
  • Zipkin trong RAM sang AWS X-Ray qua ADOT collector; log file trong volume ./logs sang CloudWatch Logs.
  • Gmail SMTP sang Amazon SES.
  • Secret viết cứng trong application*.yml sang AWS Secrets Manager.
Việc cần xử lý trước khi chuyển
  • Secret đang nằm trong code. JWT secret, X-API-KEY, key Stripe và PayPal, mật khẩu Gmail, tài khoản PocketBase, URI MongoDB và OAuth client secret đều nằm trong application*.yml; cần chuyển vào Secrets Manager và đổi (rotate) toàn bộ vì đã lộ trong git.
  • Feign client trỏ localhost. ticket-service, notification-service, auth-service và cronjob-service gọi user / station / ticket qua http://localhost:<port>; trên ECS phải đổi sang tên service trong Eureka hoặc DNS Cloud Map.
  • Callback URL. PayPal return/cancel URL và redirect OAuth2 đang là localhost; cần đổi sang domain công khai của ALB.
  • Port không thống nhất. order-service là 4009 trong application.yml nhưng 4008 trong docker-compose; notification-service là 4008 ở profile prod và 4009 ở zimaos. Cần chốt một port cho mỗi target group và health check.
  • Chatbot sang Bedrock. Đổi dependency Spring AI OpenAI sang Spring AI Bedrock Converse, chọn model và bật quyền truy cập model trong region; prompt và tham số temperature / max-tokens cần chỉnh lại theo model mới.
  • Push sang SNS. Thay Firebase Admin SDK bằng AWS SDK SNS: tạo platform application (FCM cho Android, APNs cho iOS), đăng ký FCM token hiện có thành SNS endpoint. App mobile vẫn dùng Firebase SDK để lấy token.
  • Keycloak và PocketBase trên EC2. Keycloak nên chạy 2 instance ở 2 AZ trong Auto Scaling group để không thành điểm lỗi đơn; issuer-uri của gateway đổi sang domain mới. PocketBase dùng SQLite nên chỉ 1 instance, cần snapshot EBS và chấp nhận downtime khi instance hỏng.
  • Eureka hay Cloud Map. Bản vẽ giữ eureka-service trên ECS để không đổi code; thay bằng AWS Cloud Map / ECS Service Connect là quyết định còn mở.
